# Open Knowledge Format (OKF) v0.2

> **Canonical specification:** [SPEC.md in GoogleCloudPlatform/knowledge-catalog](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md),
> Apache 2.0. This page summarises what this wiki uses; **the spec wins on any
> conflict.**

OKF is an open, vendor-neutral format for representing knowledge as Markdown with YAML
frontmatter in a directory tree. It came out of the data-catalog problem, but the core
is generic: describe a concept so an agent can filter on it before reading the whole
body. The spec's own summary of its ambition is worth quoting, because it explains why
there is no SDK: *if you can `cat` a file, you can read OKF*.

## What v0.2 adds

v0.1 already gave the descriptive vocabulary (`type`, `title`, `description`,
`resource`, `tags`). What v0.2 adds is **accountability for agent-generated knowledge**.

The reasoning is direct. A document written by a person carries implicit
accountability, because there is someone to ask. Content generated by an agent at scale
carries none of that, so provenance has to become explicit and queryable. v0.2 answers
five questions in the frontmatter: where did this come from, how much should I trust it,
is it still true, is it the current version, and was this number produced the way we
promised.

## Fields

### Required

| Field | Rule |
|---|---|
| `type` | The only always-required field. A short self-explanatory string, with no central registry. Consumers must tolerate values they do not recognise. |

### Recommended

`title` (derived from the filename when absent), `description` (one sentence),
`resource` (a URI for the underlying asset; absent on abstract concepts), `tags` (a
list).

### Provenance (§5.1)

`sources` is the list of material a concept derives from. Each entry requires
`resource`, and optionally carries `id`, `title`, `author`, `usage_count` and
`last_modified`. The sibling `usage_window` (`{from, to}`) frames those counts.

The design principle here deserves a note: the spec records **objective signals, not a
score**. The consumer infers credibility from authorship, usage and recency, because a
proprietary score does not port across organisations.

Per-claim attribution uses Markdown footnotes keyed to a source `id`, so an individual
sentence can name where it came from without dragging a citation block into the prose.

### Trust (§5.2-5.3)

```yaml
generated:
  by: claude-code/opus-5      # required inside generated
  at: 2026-07-28T00:00:00Z    # optional
verified:
  - by: human:nickssonfreitas
    at: 2026-07-28
```

The **trust tier is derived, never stored**:

| State of `verified` | Tier |
|---|---|
| key absent | `unverified` |
| only non-`human:` actors | `machine-confirmed` |
| contains a `human:<id>` | `human-reviewed` |

### Lifecycle

`status` is one of `draft`, `stable`, `deprecated`; absent means `stable`.
`stale_after` is an absolute `YYYY-MM-DD` date, and content is stale when
`today >= stale_after`. Being absolute rather than a relative TTL is deliberate: it
makes the evaluation deterministic no matter when someone reads the page.

### Actor convention (§7)

| Form | For |
|---|---|
| `<producer>/<version>` | an agent or tool (`reference_agent/gemini-2.5-pro`) |
| `human:<id>` | a person (`human:nickssonfreitas`) |
| `process:<id>` | an automated process (`process:finance-nightly`) |

Consumers classify trust by detecting the `human:` prefix, which is the whole reason the
convention is a prefix and not a separate field.

### Attested Computation (§10)

A concept type for sanctioned computations with runtime verification: `runtime`
(required), plus `parameters`, `computation`, `executor` (with `resource` and `receipt`)
and `attester` (deterministic code, **no LLM**, that compares what was declared against
what actually ran).

The distinction that matters: `verified` is **document-level** approval, slow and stored
in the bundle. Attestation is a **per-call** check, mechanical and never stored.

## Bundle structure

```
bundle/
  index.md          reserved - directory listing (§8)
  log.md            reserved - chronological history (§9)
  <concept>.md
  <subdirectory>/
    index.md
    <concept>.md
  references/       convention for external material (§6)
```

`index.md` and `log.md` are **reserved names** and cannot be used as concept documents.
Only the bundle-root `index.md` may declare `okf_version`.

## Conformance (§11)

A bundle conforms if, and only if: every non-reserved `.md` file has parseable YAML
frontmatter; every frontmatter carries a non-empty `type`; and the reserved names follow
§8 and §9.

The spec is explicit about what a consumer **MUST NOT** reject: a missing optional
field, an unknown `type`, an extra key, a broken cross-link, or a missing `index.md`.
That permissiveness is what makes the format a vocabulary rather than a straitjacket. A
broken link means knowledge not yet written, not an error.

## How this repo applies it

| Local decision | Why |
|---|---|
| **Relative** links, not bundle-relative (`/...`) | The spec allows both. GitHub resolves a leading `/` against the repository root, not the bundle root, so bundle-relative would break every link when browsing the repo. Portability loses to navigability. |
| Link and anchor checks stay **strict** | §11's tolerance binds *consumers*. We are the authors, and a broken internal link here is a mistake, not unwritten knowledge. `generate_wiki_llms.py --check` fails on it. |
| Reading order derived from `index.md` | §8 makes the index a directory listing; we make it load-bearing. A page no index links to fails the check, because a page nobody can find is a page that does not exist. |
| `sources[].resource: git:<sha>` | The commit a page was verified against is provenance, so it belongs in `sources`, not in a prose line the tooling cannot read. |
| `decision_status` alongside `status` | OKF's `status` is the *document's* lifecycle. Whether a decision was accepted or superseded is a different question, so it gets its own key. §11 permits unknown keys. |
| `_`-prefixed files skipped | `_template.md` is a conformant OKF document that documents nothing. Indexes may link it; the bundle leaves it out. |
| Free `type` values (`Subsystem`, `Surface`, `Contract`, `Invariant`…) | The spec has no central registry and tells you to pick self-explanatory values. |
| `stale_after` warns, never fails | A stale page is still a true page about an older commit. Failing CI on the calendar would train people to bump the date without re-reading. |

Conformance is checked by `python scripts/generate_wiki_llms.py --check`, which runs
§11 alongside the link, anchor and reachability gates.
